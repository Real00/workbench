# 成员评价功能（含 AI 随手记录）+ 编辑抽屉信息展示优化

## 背景结论
- 项目里已有完美模板：任务的"进度记录"（ProgressEntry，kind + content + created_at 随时追加，TaskEditor 内时间线展示），成员评价完全照此模式实现。
- AI 侧同样有模板：`add_progress_entry` 工具排队 → 用户确认 → 落库，成员评价工具照抄此链路，做到"对话里随口一提就记录"。
- 编辑抽屉（MemberEditor.vue）当前痛点：技能用逗号分隔文本框（中文输入法的"，"无法分隔、易错）；表单平铺无分组、无头像无上下文；无法在编辑时补充评价。
- 已确认：评价带分类标签（亮点 highlight / 风险 risk / 备注 note），支持删除，AI 可记录。

## 后端

**domain.py**
- 常量：`EVALUATION_KINDS = {"highlight", "risk", "note"}`、`MAX_EVALUATION_LENGTH = 2000`、`MAX_MEMBER_EVALUATIONS = 200`。
- 新增 `MemberEvaluation` dataclass（id/kind/content/created_at + `create()` 校验，仿 ProgressEntry）。
- `TeamMember` 增加 `evaluations: list[MemberEvaluation] = field(default_factory=list)`；新增 `add_evaluation()` / `remove_evaluation()`（找不到抛 LookupError，均更新 updated_at）。
- `ProgressDomainService` 新增 `add_member_evaluation()` / `remove_member_evaluation()`：取成员 → 增删 → 保存 → 返回成员。
- `validate_member_changes()` 的 `replace(member, skills=...)` 同步加 `evaluations=list(...)`。

**repository.py**：新增 `member_evaluation_from_data()`（created_at 解析、kind 兜底 note，仿 progress_entry_from_data）；`member_from_document()` 填充 evaluations（旧成员自动为空列表，无需迁移）。

**application.py**：新增两个应用方法，返回 `public_member()`（asdict 自动带出 evaluations）。

**routes.py**：`MemberEvaluationInput(kind: Literal, content: 1..2000)`；注册 `POST /api/v1/progress/members/{member_id}/evaluations`（201 返回更新后成员）与 `DELETE .../evaluations/{evaluation_id}`（返回更新后成员）。

**AI 记录评价**
- `progress/ai_tools.py`：新增工具 `record_member_evaluation(kind, content, name/member_id)` —— 解析成员（复用 `_resolve_member`）→ 校验 content 非空 → 排队 `{"op": "add_member_evaluation", "member_id", "evaluation": {kind, content}}`，仿 `add_progress_entry`；INSTRUCTIONS 里说明"对人的观察评价用该工具记录"；注册进 tools 元组。
- `pulse/application.py` `confirm()`：新增 `add_member_evaluation` 分支，调用 `progress_domain.add_member_evaluation(...)` 落库（created_at 在确认时刻生成，与任务记录一致）。
- `routes.py` / 前端已确认的操作卡片展示同步支持。

**测试**
- test_domain.py：评价校验/追加/删除；test_api.py：POST/DELETE 端点往返；test_ai.py：仿 `test_update_member_tool_queues_profile_then_confirm_writes` 验证工具排队 + confirm 落库。fakes.py 无需改动。

## 前端（frontend/src/modules/progress/ + shared/AiDock.vue）

**types.ts**：`MemberEvaluationKind`、`MemberEvaluation`、`Member.evaluations`、`MemberEvaluationInput`、`evaluationKindMap = { highlight: 亮点, risk: 风险, note: 备注 }`；`AiOperation` 联合类型加 `add_member_evaluation`。

**api.ts**：`addMemberEvaluation` / `removeMemberEvaluation`（均返回更新后的 Member）。

**store.ts**：新增 `refreshMembers()` 与 `addMemberEvaluation` / `removeMemberEvaluation` action —— 调 API 后刷新成员列表并同步 `editingMember`，抽屉不关、表单未保存内容不丢（仿 addTaskEntry + reloadEditing）。

**MemberEditor.vue 重构**（核心优化）：
- 头部：已有成员显示像素头像（MemberDeskSprite）+ 姓名 + 职位 + 状态 chip；新增保持"新增成员"。
- 表单分三组：「基本信息」（姓名/职位两列、识别色、可参与分配）、「能力与背景」、「评价记录」。
- 技能改为 chip 标签输入：Enter / 中英文逗号添加、Backspace 删除末尾、chip 带 × 移除，处理中文输入法 composition 事件，上限 20。
- 项目背景 textarea 加字数统计（x/2000）。
- 评价区块（仅已有成员显示）：类型 chip 单选 + textarea + "添加评价"按钮（即时追加不关抽屉）+ 时间线（最新在上），每条带删除 ×，交互与样式仿 TaskEditor 进度记录。

**AiDock.vue**（AI 确认卡片）：`toolLabels` 加 `record_member_evaluation: 排队记录评价`；`operationLabel` 加"给「成员」记录亮点/风险/备注"；确认卡片显示评价内容预览（仿 add_entry）。

**style.css**：新增 `.entry-kind--highlight/--risk/--note` 配色及技能 chip 输入容器样式。

**MembersPage.vue**（小改动）：成员卡片底部信息行显示评价条数。

**store.test.ts**：补 `addMemberEvaluation` / `removeMemberEvaluation` 单测。
